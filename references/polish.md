# 机翻腔润色规范

脚本默认一个字都不改正文。这一步只有用户明确要「深度润色」时才做，而且比清洗危险：

> 清洗改错了，用户翻一眼就能发现；润色改错了，可能要到第 80 章才发现伏笔没了。

---

## 先判断值不值得做

按顺序看前 3 章，命中任意两条才算机翻腔：

- 句子结构明显来自英文语序：「他做了一个决定，那就是……」「这是不可能的，就我所知」
- 「的」密集堆叠：「他的手中的那本书的封面」
- 代词泛滥，几乎每句都以「他/她」开头
- 时态残留：「他已经完成了这个动作，并且正在想」
- 数量、单位表述别扭：「他走了大约有 5 公里的距离」
- 对话标签单调或错位：「他说，微笑着」

**不是机翻腔就别润色。** 正常网文的文笔问题属于作者风格，改了就越界。

---

## 红线（不可越过）

| 类别 | 允许 | 禁止 |
| --- | --- | --- |
| 情节 | 无 | 增删事件、改变顺序、补写场景 |
| 人物 | 修称呼不一致并记录 | 改性格、改动机、加心理活动 |
| 数字 | 统一表述 | 改任何数值、日期、金额 |
| 伏笔 | 保留原句 | 「顺手」强化或解释伏笔 |
| 结构 | 合并明显断裂的句子 | 重排段落、调整章节切分 |
| 篇幅 | ±5% 以内 | 大幅扩写或压缩 |

**一句话：只换说法，不换内容。**

---

## 操作流程

1. **分批**：一次 1–2 章，单次输入不超过 6000 字。整本塞进去必然跑偏。
2. **带上下文**：给上一章最后 200 字，避免人物称谓突变。不要给全书设定，会干扰。
3. **逐段改**：保持段落数量和顺序，段内改句子。
4. **记 diff**：每章输出「原文 → 改后」的清单，只列改动句，不列未动句。
5. **回写**：改完覆盖对应章节 txt，文件名不变。
6. **收尾**：在 `out/polish-log.md` 追加本章改动条数与主要类型。

---

## 遇到问题时

| 情况 | 做法 |
| --- | --- |
| 原文明显缺字、错字导致语义不通 | 只按上下文补最保守的字，记进 diff |
| 人名/地名前后不一致 | **不改**，记进 `out/polish-issues.md` 交用户定 |
| 原文有作者本人的错别字习惯（如「的/地」不分） | 统一，但记一条说明 |
| 数字与剧情矛盾（年龄对不上） | **不改**，记录下来 |
| 大段疑似重复（非完全一致） | 不删，标出来让用户决定 |

---

## 交付格式

```markdown
# 润色记录 · 第 12 章

改动 7 句，涉及：机翻语序 4、代词冗余 2、对话标签 1

| 原文 | 改后 |
| --- | --- |
| 他做了一个决定，那就是离开这里。 | 他决定离开这里。 |
| 就我所知，这是不可能的。 | 据我所知，这不可能。 |

## 需人工确认
- 第 3 段「三年前」与第 8 章「五年前」冲突，未改
```

---

## 成本提示

百万字全量润色，按每 5000 字一次调用算，是 200 次模型调用。先让用户确认范围：

- 只润色前 10 章试读 → 判断要不要继续
- 只润色报告里标出的段落 → 成本可控
- 全量 → 明确告知耗时与费用

不要默认全量。
