# novel-tts-prep · 网文清洗与朗读化

把一本脏的网文 TXT 处理成能直接交给 TTS 朗读、也能直接阅读的**分章稿**。

四件事一次做完：**去广告去重 → 朗读化改写 → 按字数重分章 → 一章一个文件**。

> Clean messy web-novel TXT into TTS-ready, chapter-split scripts — strip ads, dedupe paragraphs, merge hard-wrapped lines, re-split by word count, and turn numbers / currency / fractions / dates / units / English words into spoken Chinese.

## 一分钟判断适不适合你

| ✅ 适合 | ❌ 不适合 |
| --- | --- |
| 整本网文 TXT → TTS 朗读稿 | 英文小说译成中文（只做音译读法，不做语义翻译） |
| 去掉站点水印、`www.xxx.com`、盗版站尾巴 | 从网站抓正文（只处理本地文件，不联网） |
| 删掉前后重复粘贴的整段 | 校对错别字、查情节漏洞、挑逻辑矛盾 |
| 一章几万字，按 3000 字左右重切 | epub / docx / mobi（请先转 txt） |
| `$50`、`3/4`、`english` 改中文读法 | 续写、改情节、调文风（润色有红线，见 `references/polish.md`） |
| GBK 乱码文件转 UTF-8 | 单章改几个错字（用编辑器更快） |
| 被硬折成每行 25 字的 TXT 还原段落 | 图片、漫画、字幕文件 |

拿不准就先跑体检，它不写任何文件：

```bash
python scripts/pipeline.py scan "书.txt"
```

输出的编码、字数、识别到的章节数，一看就知道这书能不能处理。

## 它解决什么

网上扒下来的 txt 通常长这样：

```
请记住本书首发域名：www.biquge-xxx.com，最新章节请访问本站。
　　他算了算兜里的钱，$50 大约够买 3/4 个面包，可昨天又涨价 50%。
　　手机用户请浏览 m.biquge-xxx.com 阅读最新章节
求推荐票！求收藏！（本章完）
```

TTS 读到 `$50`、`3/4`、`english` 就念错或直接跳过；广告每隔几段念一遍；一章几万字，读起来没有断点。

跑完就变成：

```
他算了算兜里的钱，五十美元大约够买四分之三个面包，可昨天又涨价百分之五十。
```

### 实际转换效果

| 原文 | 输出 |
| --- | --- |
| `请记住本书首发域名：www.biquge-xxx.com，最新章节请访问本站。` | 整行删除 |
| `求推荐票！求收藏！（本章完）` | 剔除，剩渣二次判定后删除 |
| `$50` / `3/4` / `50%` | `五十美元` / `四分之三` / `百分之五十` |
| `english` / `hello` / `okay` | `英格丽史` / `哈喽` / `欧克` |
| `2020-01-01，晚上12:30` | `二零二零年一月一日，晚上十二点三十分` |
| `5km` / `零下 20℃` | `五公里` / `零下二十摄氏度` |
| `010-88886666` | `零一零、八八八八六六六六`（加顿号，避免连读） |
| `2元` / `24小时` | `两元` / `二十四小时` |
| `率领` / `归还` / `着急` | `帅领` / `归环` / `招急`（多音字同音替换） |
| 一句一行被硬折的 txt | 合并回段落，再按句重分段到 100–150 字 |

## 设计原则

**脚本做确定性工作，模型只做判断题。**

- 正则能命中的（站点水印、纯域名行、重复段落、乱码）→ 脚本删，快且可复现
- 需要判断的（这条是广告还是作者感言？这个词该音译成什么？）→ 一律保留 + 写进报告，等人或模型决定

一个刻意的取舍：**拿不准的一律不删**。删错正文用户很难发现，多留几行广告他一眼就能看见。

## 用法

```bash
# 先体检，不产出文件
python scripts/pipeline.py scan "书.txt"

# 全流程
python scripts/pipeline.py run "书.txt" -o out --target 1500
```

### 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--target` | 1500 | 每章目标**朗读字数**（纯阅读可给 3000） |
| `--tolerance` | 0.1 | 每章字数允许的偏差比例 |
| `--keep-sections` | 关 | 保留原章边界、不全书重排。会让章号重复、字数不齐，一般不用 |
| `--join` | auto | 断行合并：`auto` 检测到一句一行才合并，`always` 强制，`never` 不合并 |
| `--english` | transliterate | `transliterate` 音译，`keep` 保留原样 |
| `--fraction` | cn | `cn`=四分之三（标准），`user`=三分之四（按分子分母顺序） |
| `--no-dedupe` | 关 | 关闭段落去重 |
| `--dedupe-near` | 100 | 只删相邻 N 段内的重复；更远的重复只记录不删 |
| `--dedupe-global` | 关 | 整本去重不限距离。多版本拼接的书用，但可能删掉不同章节的正常重复 |
| `--no-polyphone` | 关 | 关闭多音字同音替换（要干净的阅读稿时用） |
| `--renumber` | 关 | 全书重新连续编号，丢弃原标题 |
| `--merge-short` | 关 | 过短的章并入前一章 |
| `--digits` | 4 | 文件名序号位数 |
| `--scan-only` | 关 | 演算但不写文件 |

### 输出

```
out/
  chapters/0001_第一章 雨夜.txt    # 一章一个文件
  book_clean.txt                   # 全书合并稿
  report.md                        # 处理报告，先看这个
  manifest.json                     # 章序、标题、字数、来源
  uncertain.jsonl                   # 表外英文的近似音译，待复核
  flags.jsonl                       # 可疑行（已保留）
  dropped_lines.jsonl               # 每一条被删内容的审计记录（含去重段落）
```

`report.md` 末尾有「下一步」，把待办直接列了出来。`dropped_lines.jsonl` 是逐条审计：删了什么、哪条规则删的、原文第几行——怀疑误删时查这个，比翻报告表快。

### 去重的边界

只删**相邻 100 段内**的重复：排版重复、防盗章重复、草稿残留都属于这类。

隔得很远的重复分两种处理：
- 内容像广告（纯英文注入、站点尾巴）→ 照样删，这类会在几十章里各出现一次
- 中文正文的重复 → **只记录不删**，那多半是不同章节各写了一遍同一段描写，删掉会让句子前后接不上

确认要全删就加 `--dedupe-global`。

88 万字、无章节标题的书：9 秒跑完，289 章。

## 有声书：每章字数就是音频时长

**默认行为就是全书按字数重排**——每章字数接近，音频时长才稳定。

129 万字、目标 1500 字的实测对比：

| 做法 | 结果 |
| --- | --- |
| 默认（全书重排） | 857 章，平均 1500，**标准差 25**，极值 1415–1639 |
| `--keep-sections`（尊重原章） | 889 章，平均 1446，标准差 201，极值 312–1870 |

差距来自原章边界：作者这一章 945 字、下一章 3200 字，尊重边界就永远均匀不了。
所以默认不尊重边界，把全书段落拉成一条流按字数切。

**章号全书连续，原标题挪到章号后面**：

```
第一章 一九五八，老饕的噩梦            1494 字
第二章 【家常菜（入门 50/50）】（一）  1519 字   ← 原第 2 章切成两块
第三章 【家常菜（入门 50/50）】（二）  1501 字
第四章 【转职到大锅饭能手】            1498 字   ← 原章完整保留，不加序号
...
第八百五十七章 产后癫痫，乌灵参救场（六） 1458 字
```

规则：

- **章号**：全书连续重编（第一章、第二章……第 N 章），不跳号
- **标题内容**：取覆盖字数最多的那个原章标题，去掉它原来的章号
- **块序号**：该原章被切成 N 块时加（一）（二）；只切出一块就不加

某块 60% 来自原第九章、40% 来自原第十二章，标题就用「第九章的标题（四）」。报告里有一节列出所有跨章拼接的章，以及每块里各原章各占多少字。

`--tolerance` 控制允许偏差，默认 0.1。想更齐就给 0.05，但受段落粒度限制，太紧会切出碎块。

已知副作用：原书开头的书名、简介区会被卷进第一章（这些内容本身是有用的预告，但会占掉开头几百字）。

`--keep-sections` 保留原书分章结构，切出的后半段叫「第一章 XXX（续）」，章号会重复——那是「同一章的第几段」，语义上没问题，但字数不齐、不适合有声书。

## 规则可改，不用改代码

三张 JSON 在 `scripts/rules/`：

| 文件 | 管什么 |
| --- | --- |
| `ads.json` | `drop_lines` 整行删 / `strip_inline` 行内剔 / `flag_lines` 保留但报告 |
| `en2zh.json` | 英文 → 中文读法，约 300 条常用词，按分组维护 |

你的书里高频人名不在词表里，会走音节兜底（`blizzard → 布尔伊兹阿尔德`），结果会列进 `uncertain.jsonl`。补进 JSON 重跑即可，比改算法划算。

细则见 `references/rules.md`。

## 多音字：两条路

TTS 不看语境，`率领` 常读成 lǜ、`归还` 常读成 hái、`着急` 常读成 zhe。词表在 `scripts/rules/polyphone.json`，39 组 200 个词，覆盖率、行、重、长、少、为、还、都、差、转、弹、调、载、露、给、佛、的、着、强、几、中、正、数、恶、吓、缝、畜、圈、塞、劲、模、扎、扒、占、磨、空、似、可汗、单于。

怎么用取决于你的引擎。

### 路线 A：改文本（默认，任何引擎都能用）

**整词同音替换**：`率领 → 帅领`、`归还 → 归环`、`着急 → 招急`。读音对了，代价是文本里出现"错别字"，这份稿子只适合朗读。

```bash
python scripts/pipeline.py run "书.txt" -o out_tts                  # 朗读稿
python scripts/pipeline.py run "书.txt" -o out_read --no-polyphone  # 阅读稿
```

### 路线 B：喂词典（GPT-SoVITS 专用，原文一个字不动）

GPT-SoVITS 默认 `is_g2pw=True`，走 BERT 整句推理，之后由 `g2pw.correct_pronunciation()` 查 `polyphonic-fix.rep` 做手工覆盖。所以把词表导成词典就行，原文一个字都不用改。

**不需要告诉它装在哪**，脚本自己找：

```bash
python scripts/export_g2pw.py           # 自动探测并写入
python scripts/export_g2pw.py --where   # 只看探测到哪些，不写
```

探测顺序：环境变量 `GPT_SOVITS_HOME` → 当前目录逐级向上 → 各盘根目录下的 `GPT-SoVITS*` / `*sovits*` / `*AudioBook*` 等目录，再在其中按已知布局定位 `*/text/g2pw/polyphonic-fix.rep`。找到一处直接写；找到多处会列出来让你选（`--all` 全写，`--write` 指定一个）。全程 0.3 秒左右。

写入前自动备份成 `.bak`，并且只追加**词典里没有的**词；已有条目如果读音和我们不一致，会列出来并追加覆盖（`--skip-conflicts` 可保留原值）。

重启 GPT-SoVITS 生效——`polyphonic.md5` 会发现词典变了并自动重建缓存，不用手动删 pickle。

也可以手动指定：

```bash
python scripts/export_g2pw.py --write "D:/GPT-SoVITS/GPT_SoVITS/text/g2pw/polyphonic-fix.rep"
```

只有一条硬前提：`chinese2.py` 里 `is_g2pw` 必须是 `True`。若被改成 `False`（走纯 pypinyin 路径），这个词典不生效，只能用路线 A。

至于用哪个 Python 跑，不用管：脚本发现当前解释器没有 pypinyin 时，会自动找到 GPT-SoVITS 自带的那个（`.venv/Scripts/python.exe`、`python/python.exe`、`release/*/python/python.exe`）并切过去重跑。

> 实测：一份 45000 条的现有词典里，这 200 个词已经有 166 条读音正确，只补了 31 条、修正 3 条。所以词表不是越多越好——**先用 `--where` 看看你的词典覆盖了什么，再决定补哪些**。

### 加词

两条路线共用一份词表，加完重跑对应命令：

```json
{
  "char": "血", "pinyin": "xiě", "default_reading": "xie3",
  "note": "口语读 xiě",
  "rules": {"血淋淋": "写淋淋"}
}
```

`default_reading` 是 TONE3 数字声调，路线 B 要用；`rules` 是替换词，路线 A 要用。个别词读音和整组不同时，用 `readings` 覆盖：

```json
"readings": {"着手": "zhuo2", "着急": "zhao2"}
```

**两条路线都不猜。** 只处理词表里明确认可的整词。`同行`（一起走 / 同行业）、`都会`（城市 / 全都会）这类一个词两种读法的故意不收：替换成哪一种都有一半是错的。

还有一个坑：G2PW 的 `correct_pronunciation` 有逐字回退——整词没命中时会拿**单字**去覆盖所有同字。所以这张表里绝不能出现单字条目，最短也得是两个字的固定搭配。

## 已知边界

- 只吃纯文本 txt。epub/docx 请先转 txt。
- 编码自动识别 UTF-8 / GBK / BIG5 / UTF-16，输出统一 UTF-8。
- **不做英译中语义翻译**，只做音译读法。
- 分数默认标准读法 `3/4 → 四分之三`（分母在前）。
- 表外英文的兜底音译只是保底，质量不保证，必须复核。
- 去重只判「20 字以上整段完全相同」，刻意重复的短句不会被动。
- 原文件只读，绝不覆盖。

## 机翻腔润色

脚本默认**一个字都不改**正文。若要润色，由模型按章分批做，规则见 `references/polish.md`：只换说法不换内容，不改情节、数字、伏笔，一次 1–2 章，输出改动清单。

百万字全量润色成本很高，建议先润前 10 章试读再定范围。
